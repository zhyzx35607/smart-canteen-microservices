# 需求规格说明书

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 智能食堂点餐与取餐微服务系统 |
| 文档版本 | v1.0 |
| 编写日期 | 2026-05-21 |

---

## 1 引言

### 1.1 项目背景

面向校园/园区食堂场景，开发一套支持「用户在线点餐 → 商家接单备餐 → 用户凭取餐码核销 → 食堂大屏实时显示队列」的微服务系统。系统以 Spring Cloud Alibaba 为技术底座，部署于 K3S 集群。

### 1.2 项目目标

- 覆盖课程要求的 5 个必选微服务，功能端到端跑通
- 合理使用 Nacos、Spring Cloud Gateway、Sentinel 等 Spring Cloud 组件
- 提供可 K3S 一键部署的资源清单
- 编写完整的软件工程文档和测试报告

## 2 功能需求

### 2.1 用户服务（FR-U）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-U-01 | 支持手机号/学工号注册，密码使用 BCrypt 加盐存储 | 必选 |
| FR-U-02 | 支持密码登录、短信验证码登录（验证码模拟，写死 `123456`） | 必选 |
| FR-U-03 | 登录成功颁发 `accessToken`（15 min）+ `refreshToken`（7 d） | 必选 |
| FR-U-04 | 提供 `/users/me` 查询与修改接口 | 必选 |
| FR-U-05 | 提供 `/auth/refresh` Token 刷新接口 | 必选 |
| FR-U-06 | 提供 `/auth/logout` 使 Token 加入 Redis 黑名单 | 必选 |

### 2.2 菜品与菜单服务（FR-M）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-M-01 | 菜品增删改查，支持按商户隔离 | 必选 |
| FR-M-02 | 每日菜单发布，含售卖时段（如 10:30-13:30） | 必选 |
| FR-M-03 | 库存管理：下单扣减、取消回滚、低于阈值写 WARN 日志预警 | 必选 |
| FR-M-04 | 上下架切换，下架商品对 C 端不可见 | 必选 |
| FR-M-05 | 提供给订单服务的内部扣减/回滚接口（Feign） | 必选 |

### 2.3 订单服务（FR-O）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-O-01 | 下单：参数校验 → 同步调菜品服务预占库存 → 写订单 → 发送 30 min 延时消息 | 必选 |
| FR-O-02 | 订单状态机：`PLACED → ACCEPTED → PREPARING → WAITING_PICKUP → PICKED_UP`；旁路 `CANCELED` | 必选 |
| FR-O-03 | 限时取消（用户主动/超时未支付/商家超时未接单），取消时回滚库存 | 必选 |
| FR-O-04 | 取餐码生成：进入 `WAITING_PICKUP` 状态时调用排队服务入队并生成码 | 必选 |
| FR-O-05 | 提供订单详情、订单列表接口 | 必选 |

### 2.4 取餐与排队服务（FR-P）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-P-01 | 为每个窗口维护 FIFO 队列（Redis List） | 必选 |
| FR-P-02 | 叫号接口：商家触发，将订单标记为「当前叫号」，并通过 WS 广播 | 必选 |
| FR-P-03 | 核销接口：用户报出取餐码，校验通过后订单状态变更、出队 | 必选 |
| FR-P-04 | 大屏查询接口：当前叫号 + 待取列表 | 必选 |
| FR-P-05 | WebSocket 端点 `/ws/screen/{counterId}`，推送叫号事件 | 必选 |

### 2.5 网关服务（FR-G）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-G-01 | 从 Nacos 拉取路由表，按 `/api/{service}/**` 规则转发 | 必选 |
| FR-G-02 | 统一 JWT 校验（白名单：登录、注册、大屏、WS 握手） | 必选 |
| FR-G-03 | 基于 Sentinel 的服务级限流 + Redis 实现的 IP 级/用户级限流 | 必选 |
| FR-G-04 | WebSocket 代理转发到 pickup-service | 必选 |
| FR-G-05 | 统一异常响应格式 `{code, message, traceId}` | 必选 |

## 3 非功能需求

| 类别 | 需求描述 |
| --- | --- |
| **性能** | 单节点下 QPS ≥ 200；下单接口 p95 延迟 ≤ 500 ms |
| **可用性** | 任一业务服务宕机，网关返回 503 且不波及其他服务 |
| **安全性** | 密码 BCrypt 加密；JWT 带 `jti` 可吊销；JWT secret 与 `internal.token` 通过 Nacos 共享配置或 K8s Secret 注入，仓库不保留可用默认值；内部接口通过 `X-Internal-Token` 校验；输入参数 `@Valid` 校验 |
| **可扩展性** | 每个服务无状态可水平扩容；排队服务使用 Redis 作为状态外置，多副本仍可保证 FIFO |
| **可观测性** | 每个服务暴露 `/actuator/prometheus`；应用日志 stdout JSON 行，由 `kubectl logs` 收集 |

## 4 接口需求

### 4.1 对外接口

- 协议：HTTP + JSON，统一前缀 `/api`；WebSocket 端点 `/ws/**`
- 认证：除白名单外，所有请求须带 `Authorization: Bearer <token>`

| 服务 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| user | POST | `/api/user/auth/register` | 注册 |
| user | POST | `/api/user/auth/login` | 登录 |
| user | POST | `/api/user/auth/refresh` | 刷新 Token |
| user | POST | `/api/user/auth/logout` | 登出 |
| user | GET/PUT | `/api/user/users/me` | 查询/修改资料 |
| menu | GET/POST | `/api/menu/dishes` | 菜品查询/新增 |
| menu | PUT | `/api/menu/dishes/{id}` | 修改菜品 |
| menu | PUT | `/api/menu/dishes/{id}/on-shelf` | 上下架 |
| menu | GET/POST | `/api/menu/daily` | 今日菜单/发布 |
| order | POST | `/api/order/orders` | 下单 |
| order | GET | `/api/order/orders/{id}` | 订单详情 |
| order | GET | `/api/order/orders` | 订单列表 |
| order | PUT | `/api/order/orders/{id}/cancel` | 取消 |
| order | PUT | `/api/order/orders/{id}/accept` | 商家接单 |
| order | PUT | `/api/order/orders/{id}/ready` | 制作完成 |
| pickup | GET | `/api/pickup/queues/{counterId}` | 大屏数据 |
| pickup | POST | `/api/pickup/queues/{counterId}/call` | 叫号 |
| pickup | POST | `/api/pickup/pickups/verify` | 核销 |
| pickup | WS | `/ws/screen/{counterId}` | 大屏推送 |

### 4.2 对内接口（Feign，`/internal/**`）

| 调用方 → 被调方 | 接口 | 语义 |
| --- | --- | --- |
| order → menu | `POST /internal/stock/deduct` | 批量预占库存（Lua 原子扣减 Redis + 同步落库 daily_menu_item） |
| order → menu | `POST /internal/stock/restore` | 回滚库存（Redis + DB 双写） |
| order → menu | `GET  /internal/merchants/{id}` | 下单时按 merchantId 反查 counterId |
| order → pickup | `POST /internal/queues/enqueue` | 就绪入队 |
| pickup → order | `POST /internal/orders/{id}/picked` | 核销回写状态 |

### 4.3 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "traceId": "uuid"
}
```

`code = 0` 表示成功，其余按错误码表分段（10xxx 用户域、20xxx 菜品域、30xxx 订单域、40xxx 取餐域、50xxx 网关/系统）。
