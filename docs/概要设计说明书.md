## 4 子系统关系

### 4.1 服务间调用关系

```
                    ┌──────────────┐
                    │   Gateway    │
                    └──┬──┬──┬──┬─┘
                       │  │  │  │
          ┌────────────┘  │  │  └────────────┐
          ▼               ▼  ▼               ▼
     ┌─────────┐   ┌──────────┐   ┌──────────┐   ┌────────────┐
     │  User   │   │   Menu   │   │  Order   │   │   Pickup   │
     │ Service │   │ Service  │   │ Service  │   │  Service   │
     └─────────┘   └────┬─────┘   └────┬─────┘   └─────┬──────┘
                        │              │  Feign         │
                        │◄─────────────┤                │
                        │ /internal/   │                │
                        │ stock/deduct │                │
                        │              │ Feign          │
                        │              ├───────────────►│
                        │              │ /internal/     │
                        │              │ queues/enqueue │
                        │              │                │
                        │              │◄───────────────┤
                        │              │ /internal/     │
                        │              │ orders/{id}/   │
                        │              │ picked         │
```

### 4.2 关键交互时序

**下单主流程**：
1. 客户端 → Gateway → order-service
2. order-service 参数校验、幂等校验（Redis SETNX `order:idem:{key}` TTL 60s）
3. Feign → menu-service: 逐个 `GET /dishes/{id}` 校验上下架
4. Feign → menu-service: `POST /internal/stock/deduct`（Redis Lua 原子扣减 + 同步落库 daily_menu_item）
5. Feign → menu-service: `GET /internal/merchants/{id}` 反查 counter_id
6. 写 orders + order_item 表（同一事务），状态 = PLACED
7. 发送 RocketMQ 延时消息 `order.timeout`（30 min，DELAY level=16）
8. 返回 `{orderId, totalCents, status}`

**取餐主流程**：
1. 商家点击"制作完成" → order-service 生成取餐码（`{counterId}{6 位序列}`）→ Feign → pickup-service 入队
2. 商家点击"叫号" → pickup-service LPOP + SET current + STOMP `/topic/screen/{counterId}` 广播
3. 用户核销 → pickup-service 校验 code → Feign → order-service 标记 PICKED_UP，并清理 Redis 索引

## 5 数据库总体结构

每个服务独立 schema，通过 ID 引用，不建外键。所有表默认带 `id BIGINT PK`、`created_at`、`updated_at`、`deleted_at`（软删）。

### 5.1 canteen_user

| 表名 | 主要字段 |
| --- | --- |
| `user` | id, phone, student_no, password_hash, nickname, avatar, status |
| `refresh_token` | id, user_id, token_jti, expires_at |

### 5.2 canteen_menu

| 表名 | 主要字段 |
| --- | --- |
| `merchant` | id, name, counter_id |
| `dish` | id, merchant_id, name, price_cents, image_url, on_shelf, threshold |
| `daily_menu` | id, merchant_id, biz_date, sell_start, sell_end |
| `daily_menu_item` | id, daily_menu_id, dish_id, stock_init, stock_left |

### 5.3 canteen_order

| 表名 | 主要字段 |
| --- | --- |
| `orders` | id, user_id, merchant_id, counter_id, status, total_cents, pickup_code, placed_at, accepted_at, ready_at, picked_at, canceled_at, cancel_reason |
| `order_item` | id, order_id, dish_id, dish_name_snapshot, unit_price, quantity |

### 5.4 pickup-service 数据结构（Redis）

| Key | 类型 | 用途 |
| --- | --- | --- |
| `queue:{counterId}` | List | 待取队列，元素为 JSON `{orderId, pickupCode, userId}`（RPUSH 入队，LPOP 出队） |
| `queue:current:{counterId}` | String | 当前叫号的那一单 JSON，TTL 24h |
| `queue:history:{counterId}` | List (≤50) | 已叫号历史，trim 至 50 条 |
| `code:{counterId}:{pickupCode}` | String | 反向索引，值为 orderId，TTL 24h |
| `pickup:counter:{pickupCode}` | String | 反向索引，值为 counterId，核销时按取餐码定位窗口，TTL 24h |

### 6.3 统一错误码

| 分段 | 含义 |
| --- | --- |
| `0` | 成功 |
| `10xxx` | 用户域（10001 账号已存在、10002 密码错误、10003 Token 无效、10004 Token 已过期、10005 用户不存在、10006 手机号已注册、10007 验证码错误、10008 账号已被禁用） |
| `20xxx` | 菜品域（20001 库存不足、20002 已下架、20003 菜品不存在、20004 今日菜单已发布、20005 商户不存在） |
| `30xxx` | 订单域（30001 状态非法、30002 已过期、30003 不存在、30004 不可取消、30005 重复请求） |
| `40xxx` | 取餐域（40001 取餐码不存在、40002 重复核销、40003 队列为空） |
| `50xxx` | 网关/系统（50001 限流、50002 鉴权失败、50003 服务暂不可用） |
| `90000` | 未知异常（兜底） |
